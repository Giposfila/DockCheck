# DockCheck

Локальная предварительная проверка DOCX по СТУ СФУ 7.5–07–2021 и отдельным
пользовательским требованиям. Документ разбирается в браузере; сервер обработки,
передача документа внешним сервисам и автоматическое исправление отсутствуют.

Каталог требований и автоматическая проверка — разные возможности. Каталог
учитывает формальные нормы, условия, разрешённые варианты и рекомендации.
Большая часть структурных, геометрических и внешних требований пока получает
`unknown`. Это не подтверждение соответствия и не обнаруженное нарушение.

## Использование

```sh
npm ci
npm run dev
```

Vite слушает порт 4173 и может выбрать следующий свободный. Загрузите DOCX
размером до 25 МиБ. В настройках укажите доступный контекст работы; остальные
поля можно оставить неизвестными.

Настройки разделены на контекст, состав по заданию, реквизиты и комплект,
нумерацию и ссылки, оформление СТУ и локальные дополнения. Поддерживаются все
виды работ из области применения стандарта. Согласование ВКР, число
консультантов, система документации и наличие отдельных материалов хранятся
отдельно. Формы титула выбираются по виду работы, не по имени загруженного файла.

Профиль имеет `schemaVersion: 2`, собственные id/версию и ссылку на версию
каталога `stu-2021.1`. При сохранении загруженный документ пересчитывается.
Импорт применяется целиком после валидации. Неверная схема, неизвестные поля,
повреждённые значения и отсутствующий источник локального требования
отклоняются. Экспорт профиля, каталога с матрицей и отчётов доступен локально.

Профиль хранится под `dockcheck-work-profile-v2` в localStorage. Старый
`dockcheck-sfu-requirements-v1` мигрирует в отдельный локальный шаблон; старые
`requiredSections` и порог содержания сбрасываются с объяснением. Документ и
отчёт остаются в памяти. Реквизиты и введённые пользователем внешние сведения
являются частью сохраняемого профиля.

## Нормативные данные

В `src/requirements/` находятся:

| Файл | Назначение |
| --- | --- |
| `schema.ts` | Схема правила, модальности, ограниченные операции, трёхзначная логика, проверки целостности |
| `catalog.ts` | Неизменяемый каталог, матрица `COVERAGE`, исключения `EXCLUSIONS`, титульные формы, размеры схем и внешние зависимости |
| `source-index.json` | Постраничные/построчные локаторы и хеши фрагментов локального PDF; без его текста |
| `sourceCoverage.ts` | Связи индексированных фрагментов с решениями матрицы |
| `profile.ts` | Профиль работы, локальные требования, комплект, внешние сведения, валидация и миграция |
| `engine.ts` | Применимость, предикаты и реестр фактической поддержки |

Исходный PDF имеет 61 страницу. Индекс содержит 400 текстовых/графических
фрагментов. Матрица разделяет формальные нормы, рекомендации, разрешения,
примеры, определения и исключённые субъективные требования. Смешанные пункты
связываются с несколькими решениями. Приложения А, П и У не превращены в
обязательные шаблоны; темы и номера страниц примера Т не обязательны.

Индекс можно воспроизвести локально при наличии Poppler:

```sh
python3 scripts/inventory-standard.py
```

Проверка связности индекса подтверждает учёт фрагментов, а не независимую
содержательную сертификацию каталога. Связи на уровне пункта объединяют его
текстовые блоки; тесты не доказывают атомарность каждой интерпретации.
Размеры рамок и надписей перенесены с изображений страниц 45–48;
арифметические суммы проверены. Независимая экспертная сверка всех размеров
и внутренних связей схем остаётся необходимой.

Полные тексты внешних ГОСТов не включены. Обозначения и редакции сохраняются
по исходному СТУ; автоматического обновления редакций нет. Перечень зависимости
не означает наличие внешнего нормативного валидатора.

`TASK.md`, `CТУ.pdf` (латинская C), `СТУ.pdf` и локальный `AGENT.md` исключены
из Git. Для запуска приложения исходный PDF не требуется.

## Достоверность результатов

| Статус | Значение |
| --- | --- |
| `pass` | Проверяемое свойство или условие подтверждено в заявленных границах |
| `fail` | Есть доказательства отклонения в заявленных границах |
| `unknown` | Неизвестна применимость, роль, факт либо отсутствует реализация/внешнее доказательство |
| `not_applicable` | Неприменимость установлена; разрешённая конструкция не требуется сама по себе |

Разрешение хранит допустимый вариант, а не обязанность его использовать.
Ограничение выбранной формы Ж проверяется отдельным обязательным правилом:
консультантов не более двух. Нарушения рекомендаций, в том числе кегля таблиц,
показываются в отдельном фильтре и не включаются в обязательные нарушения.

Отчёт различает исходный стандарт, локальные сравнения и ограничения анализа.
Локальные правила не перезаписывают СТУ: сохраняются обе оценки и их источники.
Конфликты показываются рядом с профилем. Внешние свидетельства и заявленный
комплект сохраняются отдельно; простое упоминание файла не подтверждает его
содержимое или соответствие.

Начальная проверка по СТУ консервативна: обычная строка, стиль Heading или
соседняя подпись дают кандидата роли. Они не доказывают структурную функцию.
Поэтому даже известный шрифт может получить нормативный `unknown` из-за роли.
Дополнительный локальный шаблон позволяет явно сравнивать эвристические роли
с заданными пользователем параметрами; такие результаты помечены отдельно.

Для листов без рамки поддержаны вертикальные поля 30/10/20/20 мм и
горизонтальные 20/20/30/10 мм (слева/справа/сверху/снизу). Неизвестная
ориентация или вид работы сохраняет неопределённость; зеркальные поля требуют
отдельной модели внутренних/внешних полей. Геометрия рамки не заменяется полями.

Техническая погрешность сравнения — 0,02 мм (один twip ≈0,01764 мм),
0,01 пт и 1/240 строки с поправкой на арифметику. Это погрешности единиц OOXML,
а не допуски стандарта. Предикат и метаданные полей используют одну точность.

Пункт 6.4.1 только рекомендует отсутствие содержания при объёме до 24 страниц
включительно. Обязательности содержания свыше этого порога нет. Введение,
заключение и список источников не требуются безусловно для всех работ.

## Анализатор и ограничения

Анализатор читает ZIP/relationships/XML, каскады стилей и темы, свойства
абзацев/runs/секций, условные стили таблиц, геометрию прямых свойств, используемые
колонтитулы, заметки и текстовые блоки. Правки не принимаются автоматически;
неподдержанное содержимое фиксируется с расположением.

Сохраняются исходная текстовая проекция, диапазоны UTF-16, цитаты и источники
свойств. Кандидаты структуры, дерево заголовков, области приложений,
библиографические строки и отсылки хранятся с причинами неоднозначности.
OMML извлекается как объект с исходным текстом; полноценного математического
анализатора, нумерации формул и семантического сопоставления нет.

Видимые номера вычисляются только для поддержанного одноуровневого decimal
с явным стартом и шаблоном `%1`, `%1.` или `%1)`, раздельно по историям и numId.
Другие уровни, форматы и неподдержанные цепочки остаются unknown/unsupported.
Вычисление номера не доказывает нормативную корректность перечисления.

Движка вёрстки нет. Сохранённые `lastRenderedPageBreak` дают только ориентир
между двумя маркерами; они не доказывают объём реферата, начало элемента,
печатные номера, содержание или положение объекта. PAGE доказывает лишь
обнаруженное поле и доступные свойства его абзаца. Полнота нумерации остаётся
отдельным неизвестным требованием.

Нет полного разрешения сложных письменностей, условных стилей объединённых
таблиц, всей геометрии/границ, всех полей Word и структурной классификации.
Отдельные чертежи, слайды и физические процедуры не анализируются по DOCX.
Плотность заполнения 70 % сохранена как норма без придуманной методики площади.
Нет анализа плагиата, научной достоверности, новизны или смысловой уместности.

## Отчёт и API

Текстовый экспорт содержит все результаты, включая успехи и неизвестные:
версию профиля, нормативный источник, отдельный источник OOXML, модальность,
применимость, код причины, доказательства, диапазоны, цитату и технический допуск.
JSON-экспорт имеет оболочку `schemaVersion: 1` и сохраняет полный отчёт.
Количество пройденных результатов не является процентом соответствия всему СТУ.

```ts
import { checkDocx } from './src/checker';
import { DEFAULT_PROFILE } from './src/requirements/profile';
const report = await checkDocx(data, DEFAULT_PROFILE);
```

По умолчанию используется новый профиль с неизвестным контекстом. Для
совместимости явный аргумент старого типа `Requirements` принимается как
локальный шаблон (`legacy-api`); он не подменяет нормативный каталог.

## Проверка

```sh
npm test
npm run build
```

93 теста включают прежние сценарии анализатора, целостность каталога и индекса,
применимость, альтернативы, исключения, обе ориентации, миграцию, конфликты,
модальности, причины, UTF-16, экспорт и ограниченные счётчики.

Пять исходных DOCX синтетические. Добавлен документ, экспортированный
конвертером ONLYOFFICE из независимо заданного RTF, с обратным чтением движком
редактора. Воспроизводимость и ограничения описаны в
[tests/fixtures/ONLYOFFICE.md](tests/fixtures/ONLYOFFICE.md).
Это не подтверждает открытие в GUI Word/ONLYOFFICE или совместимую вёрстку.
Эталонные изображения и подтверждённая пагинация остаются отдельной работой.

Браузерный сценарий требует отдельно установленного Playwright и Chromium:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
DOCKCHECK_URL=http://localhost:4173 node scripts/check-ui.mjs
```

Он проверяет пять исходных фикстур, поиск/цитаты, буфер обмена, фильтры,
мобильную ширину 390 px, клавиатуру диалога, локальный и исходный профили,
пересчёт, отклонение повреждённого импорта, экспорт и отсутствие запросов
передачи документа. Скриншоты и скачанные отчёты записываются в `/tmp`.

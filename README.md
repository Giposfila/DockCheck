# DockCheck

Локальный браузерный анализатор оформления DOCX. TypeScript, Vite, JSZip,
@xmldom/xmldom, Vitest. Документ не отправляется на сервер и не изменяется.
PDF, OCR и автоматическое исправление не поддерживаются.

```sh
npm ci
npm run dev
npm test
npm run build
```

Ветка `develop` создана от `c5f99ac` (текущий коммит `main` на начало работы).
Исходная реализация импортирована из локального `origin/master` без изменения
основания ветки. Файл задания `AGENT.md` и варианты регистра исключены из Git.

## Архитектура

- `src/analyzer/package.ts`: ZIP, XML, relationships и относительные пути частей.
- `model.ts`, `extract.ts`, `properties.ts`: модель, явные значения, единицы,
  происхождение, разрешённые/неизвестные/неподдерживаемые свойства.
- `styles.ts`: docDefaults, стили по умолчанию, basedOn, защита от циклов,
  переключение bold/italic в стилях.
- `theme.ts`: тематические шрифты и базовые тематические цвета.
- `numbering.ts`: уровни списков, отступы, старт и overrides.
- `tables.ts`: базовые стили таблиц, простые условные области, исходная геометрия.
- `resolve.ts`: построение модели и обход связанных частей.
- `src/checks/formatting.ts`: проверки модели без доступа к XML.
- `src/profiles/default.ts`: сохранённый настраиваемый профиль.
- `src/checker.ts`: публичный `checkDocx`, контекст секций, сбор отчёта.

`checkDocx(data, requirements)` возвращает `document`, `results`, `coverage`,
совместимые с интерфейсом `findings`, `manualChecks` и статистику.
Результат содержит стабильный `ruleId`, отдельные status и severity, место,
факт, требование, источник, пояснение и рекомендацию.
`pass` относится только к конкретному правилу в указанном месте.
Неизвестные фрагменты сохраняются отдельно от найденных нарушений.
Интерфейс показывает реальное покрытие; текстовый экспорт включает все проверки
с источниками и рекомендациями. Количество страниц не оценивается.

## Реализованное извлечение

| Область | Поддержка |
| --- | --- |
| Текст | Каждый фрагмент: шрифт по группе символов, размер в пт, bold/italic, подчёркивание, цвет, индекс, межсимвольный интервал; явные и итоговые свойства |
| Абзацы | Выравнивание, отступы в мм, первая строка/выступ, интервалы до/после в пт, line и lineRule, автоматические/контекстные интервалы, табуляции, keepNext/keepLines/pageBreakBefore/widowControl |
| Секции | Размеры, ориентация, поля, переплёт, колонки, расстояния до колонтитулов, формат и начало нумерации |
| Списки | numId/ilvl, abstractNum, lvlOverride, startOverride, формат/текст/старт/перезапуск, отступы и табуляции уровня |
| Таблицы | Основной стиль и basedOn, wholeTable и одиночная область first/last row/column по tblLook; tblPr/tblGrid/trPr/tcPr сохраняются с исходными единицами OOXML |
| Колонтитулы | Связанные нижние колонтитулы по секциям с наследованием, titlePg и evenAndOddHeaders; PAGE и выравнивание его собственного абзаца; оформление фрагментов поля |
| Структура | Основной текст, вложенные таблицы, гиперссылки, content controls, текстовые блоки, связанные сноски/концевые сноски; пустые абзацы, табы и разрывы |

Числовые значения проверяются на конечность. Нет произвольной подстановки
Times New Roman, 14 пт или нуля при отсутствии данных. Булевы false/0/off
учитываются; отсутствие локального свойства не сбрасывает наследование.
Шрифт и кегль проверяются также в таблицах. Строка `1 Текст` не считается
заголовком только по номеру. Подписи таблиц и рисунков ищутся рядом с объектом;
отсутствие распознанной подписи требует ручной проверки.

Профиль унаследован от прежней реализации. Его значения и ссылки на СТУ СФУ
7.5-07-2021 **не являются независимо проверенной копией стандарта**. Новые
нормативные требования не добавлялись. Машинные результаты обозначены как
сравнение с настраиваемым профилем.

## Конкретные ограничения

- Это ограниченная поддержка Transitional OOXML; Strict OOXML и неизвестные
  пространства имён не интерпретируются как поддерживаемые данные.
- Не реализован движок вёрстки: нет точных страниц, фактического отображения,
  проверки положения объектов, достаточности содержания или наличия шрифтов.
- Выбор шрифта по алфавиту упрощён; font fallback, language-specific supplemental
  theme fonts, bidi, hint и сложные скрипты требуют дальнейшей реализации.
- Тематические tint/shade цветов дают unsupported; сложная каскадная композиция
  взаимосвязанных атрибутов шрифтов/интервалов полностью не покрыта.
- Условное чередование полос и углы таблиц, пересечение условных областей,
  cnfStyle, gridSpan и вертикальные объединения не разрешены. Свойства таких
  абзацев получают unsupported, а проверки — unknown. Геометрия таблиц пока
  сохраняется в исходных единицах, без самостоятельных правил соответствия.
- Зеркальные поля представлены неизвестным свойством. Сложные списки со
  styleLink/numStyleLink и вычисление видимых номеров не реализованы.
- Верхние колонтитулы извлекаются из связанных частей, но их области действия
  по секциям не разрешены. Не проверяются фактическое присутствие PAGE на каждой
  странице, арабское отображение поля и связи сложных составных полей.
- Правки ins/del/move не принимаются автоматически: содержимое исключается с
  явным ограничением. Изменённые свойства не смешиваются со старой версией.
- Классификация ролей ограничена явными стилями/контекстом. Нет полноценного
  семантического распознавания заголовков, подписей и библиографии.
- Набор правил для ролей пока ограничен общим настраиваемым профилем; исключения
  для разных видов таблиц/сносок требуют отдельной нормативной базы.
- Content types присутствуют в комплектных фикстурах, но полный валидатор OPC
  и всех типов связей пока не реализован.

## Проверка качества

`npm test`: 24 теста; `npm run build`: TypeScript и Vite проходят.
Проверены defaults/basedOn/rStyle, темы и смешанные алфавиты, прямой шрифт поверх
темы, переключатели, интервалы auto/exact/atLeast, списки, простые условные стили
и вложенные таблицы, циклы, PAGE в другом абзаце, наследуемые/неиспользуемые
колонтитулы, пустые абзацы/гиперссылки/сноски, правки, повреждённый XML и NaN.

В `tests/fixtures` находятся три комплектных DOCX (OPC content types, root и
part relationships), генератор `node tests/fixtures/generate.mjs` и тесты:
`correct.docx`, `incorrect.docx`, `partial.docx`. Они синтетические; ручное
открытие в Word/LibreOffice не выполнялось.

В Chromium проверены загрузка и отчёт для всех трёх файлов:
корректный — 0 нарушений, ошибочный — 2 нарушения, частично неподдерживаемый —
11 неопределённых результатов. Проверен переход к ручным проверкам; ошибок
JavaScript не было. Скриншоты проверки сохранены в `/tmp/dockcheck-*.png`.
